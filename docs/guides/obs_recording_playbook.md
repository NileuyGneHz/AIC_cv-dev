# OBS 录制操作手册（阶段性汇报 / 省赛提交视频）

> 定位：**照着做就能录出一条能交的视频**。不讲原理，只讲「点哪里、看什么、说什么」。
> 适用：2026-10-20 的 M3 版本（置物台上料 → 固定相机识别 → 吸盘取料 → 货架 4 列 × 3 层）。
> 原理与排障见 `simulation_manual.md`；本文件只服务录制。

---

## 0. 录制前 60 秒清单

按顺序敲，四步都过再开 OBS。

```bash
cd ~/AIC_cv-dev

# 1) 确认没有残留实例（有输出就先杀掉，否则画面会串台）
pgrep -af "gzserver|score_node|gantry_controller"

# 2) 确认没有别的程序占着 8080
ss -ltnp | grep 8080 || echo "8080 空闲"

# 3) 清掉旧产物，避免把上一轮的图当成这一轮的
rm -rf logs/storyboard logs/sim_results_*.csv

# 4) 起演示（真视觉；有显示器就加 gui:=true）
ros2 launch aic_dashboard dashboard.launch.py vision_backend:=trad
```

浏览器打开 `http://127.0.0.1:8080`，确认三件事：

| 检查项 | 合格表现 |
|---|---|
| 全景画面 | 能看到置物台（蓝色台面 + 黄色物料）、货架 4 列 × 3 层、供料管 |
| 末端相机 | 有画面（不是黑块/灰块） |
| 计分板 | 12 格为灰色「待巡视」，比分 0 / 0 |

> 起完后**先别录**，让它跑完一轮当热身。第二轮起跑前按 F9 开始录——第一轮的价值是确认「12 格全绿」，
> 万一第一轮就出问题，直接 Ctrl-C 重来，不浪费一次录制。

## 1. 画面怎么摆（三种方案，按可用的显示器选）

### 方案 A（推荐）：只录看板单窗口

一条命令、一个浏览器窗口、一个 OBS 源，最不容易出错，也直接满足「单窗口可录屏」这条硬指标。

```bash
ros2 launch aic_dashboard dashboard.launch.py vision_backend:=trad
```

- OBS 源：**窗口采集** → 选 Chrome/Edge 的 `AIC 判分看板` 窗口
- 画面里同时有：全景（抓取全过程）+ 末端相机（识别输入）+ 态势图（12 块物料位置）+ 12 格判分
- 缺点：没有 Gazebo 原生 GUI 的菜单栏/播放条，但**评审看的是过程与结果，不是窗口外壳**

### 方案 B：看板 + Gazebo GUI 双源（有显示器时最直观）

```bash
ros2 launch aic_dashboard dashboard.launch.py vision_backend:=trad gui:=true
```

- Gazebo GUI 会另开一个窗口：左边是模型树，下方是播放/暂停条，中间是三维场景
- OBS 用**两个窗口采集**，左右并排（左 Gazebo、右看板），或看板全屏 + Gazebo 画中画
- 注意：Gazebo GUI 窗口不要手动拖动视角（无人机位由看板按钮控制），否则「无人为干预」这条会被质疑

### 方案 C：只录 Gazebo GUI

仅在需要强调「这是真物理仿真」时用。缺点是没有判分画面，评审看不到「放对/放错」，不推荐单独使用。

> 本手册的插图全部来自 Gazebo 的 `scene_cam` 渲染管线（与 GUI 里的「全景俯视」机位同一条管线、同一帧），
> 所以你录出来的画面与手册插图在构图上是一致的，只是多了窗口边框。

## 2. OBS 设置（一次配好，之后不用动）

| 项 | 值 | 说明 |
|---|---|---|
| 画布分辨率 | 1920 × 1080 | 低于 1080P 会被赛区退回 |
| 输出分辨率 | 1920 × 1080 | 「设置 → 视频 → 缩放分辨率」 |
| 帧率 | 30 fps | 仿真 15 Hz 相机，30 fps 足够，码率更省 |
| 录制格式 | mp4（H.264） | 或 mkv，录完再「重新封装」成 mp4 |
| 码率控制 | CQP 18–20 | 文字与判分格要清晰，别用「低质量」预设 |
| 音频 | 默认麦克风，48 kHz | 若要旁白；纯录屏可关 |
| 源 | 窗口采集（方案 A/B） | 不要用「显示器采集」，会把桌面图标录进去 |

录制前点一次「开始录制」，看 OBS 右下角是否在走秒、磁盘剩余空间 > 5 GB。

→ ④ 放进对应类型列的最低空层（每格一块，不叠放）。货架第 1/2/3 层高度分别是 0.10 / 0.16 / 0.22 m。

## 4. 分镜脚本（本轮实测时间轴，照着念即可）

以 M3 真视觉单轮为准：整轮 **约 145 s**（12 轮上料），加上收尾定格，成片约 **2 分 40 秒**。
时间码是实测值，允许 ±3 s 漂移，旁白跟着画面走，不要抢。

| 时间码 | 画面（看板上该看到什么） | 动作/事件 | 旁白（可直接念） |
|---|---|---|---|
| 0:00–0:08 | 全景：供料管里叠着 12 块物料，货架 12 格全空 | 仿真启动、控制握手 | 「这是 ROS 2 + Gazebo 搭建的仓储分拣仿真，12 块带缺陷的圆形铁片从供料管逐块上料。」 |
| 0:08–0:14 | 一块物料从供料管「飞」到蓝色置物台 | `set_pose` 上料 | 「每轮先把一块物料传送到置物台，台面同一时刻只有一块，避免遮挡。」 |
| 0:14–0:18 | 龙门退到偏移位，末端相机画面出现铁片 | 固定相机拍照 | 「龙门让开光路，置物台正上方的固定相机拍照，视觉开始判型。」 |
| 0:18–0:22 | 末端相机画面 + 判分格变琥珀色 | 视觉输出 1–4 类 | 「四类缺陷：划痕、污渍、缺角、孔洞，传统视觉在 0.3 秒内给出类型。」 |
| 0:22–0:30 | 吸盘下探贴住铁片，物料随龙门抬起、横移 | 吸附 + 搬运 | 「吸盘下探吸附，靠 DetachableJoint 模拟真空吸附，物料跟着龙门走。」 |
| 0:30–0:36 | 物料落到货架对应类型列的最低空层，判分格变绿 | 放入 + 判分 | 「按类型放进对应的列，从第一层往上填，放对即变绿，比分实时累加。」 |
| 0:36–2:10 | 上述过程重复 11 次，货架逐格填满 | 第 2–12 轮 | 「后续 11 轮完全自动，无人工干预；中途任何一次识别超时都会被记为 TIMEOUT 并继续巡视。」 |
| 2:10–2:25 | 最后一格填满，12 格全绿，比分 12 / 0 | 终态 | 「12 块全部放对，零超时、零错放。」 |
| 2:25–2:40 | 停留在终态画面 | 定格 | 「整套链路：视觉识别 → 行为树决策 → 龙门控制 → 物理抓放，全部在仿真内闭环。」 |

**三句必须念到的话**（评审关注点）：

1. 「决策层零改动」——同一套行为树可以对接真机；
2. 「视觉是传统算法，不是读真值」——`vision_backend:=trad` 就是证据；
3. 「放对变绿、放错变红」——判分逻辑与官方平台一致。

## 6. 录完 3 分钟内自检（不通过就重录，别硬交）

```bash
cd ~/AIC_cv-dev

# 1) 抓放必须成对：两个数都应是 12
grep -c "吸盘吸附" logs/sim_launch_*.log | tail -1
grep -c "吸盘断气" logs/sim_launch_*.log | tail -1

# 2) 决策结果表：12 行且全 OK
column -s, -t logs/sim_results_*.csv | tail -13

# 3) 终态截图（自己留档，也可作为视频结尾的定格）
ls -t logs/storyboard/*final*.png | head -1
```

| 自检项 | 合格线 | 不合格怎么办 |
|---|---|---|
| 12 格颜色 | 全绿 | 有红/琥珀 → 重录，先查 §6 |
| 比分 | 12 / 0 | 同上 |
| 吸附/断气 | 各 12 | 少一块 = 物料没放下，重录 |
| 视频时长 | 2–3 分钟 | 过短说明中途崩过 |
| 画面清晰度 | 能看清库位编号与类型字 | 提高 OBS 码率到 CQP 16 |

## 7. 录制中出问题怎么办（红线：不许改脚本）

| 现象 | 处置 |
|---|---|
| 看板画面黑屏 | 不要重启 OBS；等 5 s，若仍黑，Ctrl-C 重跑（本条视频作废） |
| 某格变红 / 变琥珀 | 让它跑完，记录现象，本条作废重录；不要中途干预 |
| 仿真卡住不动（> 30 s 无变化） | Ctrl-C，本条作废；按 `simulation_manual.md` §11 排查 |
| 浏览器崩了 | 重开浏览器，OBS 继续录也没意义（画面断了）→ 作废重录 |
| 录制中误触 Gazebo 视角 | 用看板「全景俯视」按钮复位，或本条作废 |

**录制期间绝对不要做的事**：改任何 `.py`/`.sh`（bash 边读边执行，正在跑的实例会当场死）、
`colcon build`、`pkill`、开第二个仿真实例（会串台）。

## 8. 一次录制的完整命令序列（复制即用）

```bash
# 终端 1：起演示（无显示器去掉 gui:=true）
cd ~/AIC_cv-dev
source /opt/ros/humble/setup.bash && source install/setup.bash
ros2 launch aic_dashboard dashboard.launch.py vision_backend:=trad

# 浏览器：http://127.0.0.1:8080
# OBS：窗口采集该浏览器 → 开始录制 → 等它自己跑完 → 停止录制

# 终端 2（可选）：同步留一份 Gazebo 分镜，作为视频封面/技术文档插图
ros2 run aic_gazebo_sim capture_storyboard.py \
    --ros-args -p out_dir:=logs/storyboard_$(date +%H%M)
```

> `capture_storyboard.py` 只订阅不发布，与录制完全并行，不会影响判分。
> 它会在最后一轮放完后自动退出，产物为按时间编号的 PNG + `storyboard.txt` 清单。
