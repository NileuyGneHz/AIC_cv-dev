## 3. 官方平台的硬参数（可直接当「对标依据」写进技术文档）

来源：说明书 2.2.2 / 2.2.3 / 3.2.3。

- 库位：**12 个 = 4 列 × 3**，四列分别对应四类缺陷；每库位只允许一块正确物料，堆叠不算分。
- 判定反馈：放置正确物料**变绿**，错误**变红**，系统自动计分。
- 三轴行程：X 0–300、Y 0–300、Z 0–200（mm），速度档 1–5。
- 相机：点「拍照」把当前画面发给视觉程序，图片落在 `received_images/`。
- 通信：TCP 字符串协议 —— `Camera:Trigger=True` / `Camera:Start=True` / `Camera:Result={值}`；
  错误码 −1 图像不完整、−2 超时、−3 通信错误、−4 连接拒绝。
- 运行方式：先导入视觉算法，再导入控制逻辑，两个连接自动建立，一键全自动。

> 我们的 Gazebo 仿真目前是 4 格码放（x = −0.36/−0.12/+0.12/+0.36 对应四类），
> 与官方「4 列 × 3」结构一致，只是每型 1 格靠同型叠放消化 3 块。这一点在技术文档里可以正面对齐。

## 4. 用「同类型数字孪生平台」的过审硬指标

官方平台自带判分变色，评委看画面就能判对错；换成自建平台，这个能力必须自己补回来，
否则会踩「视频需清晰反映比赛结果」这一条。四条硬指标：

| # | 指标 | 我们的现状（2026-10-20） | 差距 |
|---|---|---|---|
| 1 | 仿真内置相机取图（实时渲染，非预置图片） | 已有，真视觉节点取 Gazebo 相机帧 | 无 |
| 2 | 12 库位 + 物料生成/堆叠物理 | 已有，DetachableJoint + 叠放触底判据 | 无 |
| 3 | **实时判分可视化（正确绿/错误红 + 计分板）** | **没有**，只有 CSV 与日志（`src/` 内无判分/GUI 节点） | **必须新增** |
| 4 | 单窗口可录屏（仿真画面 + 识别结果 + 得分） | 有相机视图窗口（`docs/guides/assets/sim_camera_view.png`），无合成面板 | 需合成 |

### 候选平台对比（若不用官方版）

> 许可与价格随版本变动，以下标注均为推断口径，选用前以各官网为准。
> 核心不在平台名气，在**能不能把上表第 3、4 条做出来 + 11-02 前来得及**。

| 平台 | 许可/成本 | 任务适配（龙门三轴+相机+12 库位） | 迁移工作量 | 结论 |
|---|---|---|---|---|
| **Gazebo/Ignition Fortress（自建）** | 开源，零成本 | 已闭环：12 库位 + DetachableJoint 抓放 + gz 相机 + 真视觉，12/12 全对 | 0（只补判分板） | **首选，不换** |
| CoppeliaSim | 教育版免费，Win/Linux | 内置 vision sensor + Python/Lua API，龙门用 prismatic 关节即可 | 高：世界、控制器、相机桥全重写，且**视觉判据要按新渲染器重新整定** | 备选第一名，仅在群里否掉 Gazebo 时启用 |
| Webots | 开源（Apache-2.0） | vision sensor 成熟，CartesianRobot 节点现成 | 高（同上） | 备选第二名，比 CoppeliaSim 更简单但渲染一般 |
| NVIDIA Isaac Sim | 免费，吃显卡（RTX 建议 8G+ 显存） | 保真度最高，ROS 2 桥原生 | 最高：学习曲线陡 + GPU 负载 | 13 天内不现实，不建议 |
| Unity / Unreal | 学生免费 | 画面最漂亮（适合录视频），物理/机器人集成要自建 | 很高：要自写三轴运动学 + 相机流 | 除非有美术展示需求，不建议 |
| RoboDK | 商用，教育版收费 | 偏工业机械臂离线编程，直角坐标龙门支持一般 | 中 | 与本赛题形态不匹配，不推荐 |
| Visual Components | 商用（较贵） | 产线仿真强 | 中 | 经费有限不考虑 |
| NX MCD / 汇川 VUP / TIA+PLCSIM | 商用，看学校授权 | 偏 PLC 信号级孪生，视觉取图要自接 | 高 | 国赛 PLC 路线可回头看，省赛不用 |

**换平台的真实成本**（为什么首选是"不换"）：视觉阈值（`elong/frac/circ/rad/drop`，
`defect_classifier.py`）是在 Gazebo 渲染上按盘半径归一化整定的（`sim_layout.yaml` camera 段
注释里 r≈83 px 那套标定）；换渲染器 = 换图像统计分布 = 全部判据重新标定 + 60 位点回归重跑。
13 天倒计时里这是纯风险，没有收益。**先在群里确认 Gazebo 可用，再谈别的。**

## 5. 录像硬要求（第七届官方流程原文口径，2026 版以队长群为准）

1. 自备 **1 个固定直播机位**，架在场地四周，完整拍到选手在仿真平台参赛全过程。
2. **仿真软件录屏**：视频**无剪切**，过程中设备/软件自动运行、**无人为干预**，清晰反映比赛结果。
3. 流程视频**一镜到底**，不允许加速、删减、拼接、特效；违反按作弊处理。
4. 分辨率建议 1080P 及以上（长沙理工等赛区通知口径：横屏、≥1080P、画面声音清晰）。
5. 提交物：技术文档（**PPT 形式**，含编程逻辑、算法特点、图像集展示）+ 程序源代码 + 竞赛任务完成视频。

## 7. 用这套仿真的完整参赛流程（从现在到 11-02）

### 阶段 0 · 口径确认（今天就做）

队长在 QQ 群 887553789 问清"用自建 Gazebo 数字孪生录制是否认可"，**截图存档**。
官方只写了"官方统一的仿真平台或真实设备"，第三方平台属于口径问题，不能默认可以。

### 阶段 1 · 录制环境（一条命令）

```bash
cd ~/AIC_cv-dev && source install/setup.bash
ros2 launch aic_dashboard dashboard.launch.py vision_backend:=trad
```

起齐「仿真 + 决策 + 判分看板」；浏览器开 <http://127.0.0.1:8080>，即"相机流 + 12 库位绿/红 +
计分板"单窗口。录制前先跑 `./scripts/verify_sim_m2.sh` 确认仍是 12/12（防并发执行者串台：
起跑前 `pgrep -af gzserver`，看到两个就停）。

### 阶段 2 · 录制布置（双录同跑，各一镜到底）

| 录制 | 设备 | 内容 | 对应提交物 |
|---|---|---|---|
| 录屏 | OBS 录浏览器看板窗口 | 仿真全自动跑 12 位点，无剪切、无干预，1080P | 竞赛任务完成视频 |
| 机位 | 手机/相机固定在三脚架，拍选手+屏幕全景 | 选手全程在操作位，不遮挡 | 参赛视频（固定机位） |

录前 checklist：关闭无关窗口与系统通知；`jitter_seed` 固定；磁盘余量；看板页面时间戳可见；
开录 → 起仿真 → 自动跑完（约 80–100 s）→ 结果定格 ≥5 s → 停录，中间不碰键盘鼠标。

### 阶段 3 · 材料四件套

1. 竞赛任务完成视频（阶段 2 录屏）。
2. 参赛视频（阶段 2 固定机位）。
3. 技术文档（PPT 形式）：编程逻辑（决策 BT + 视觉判据）、算法特点（按盘半径归一化、
   触底判据、多种子回归）、图像集（`docs/guides/assets/vision_atlas.png` 现成）、
   **平台对标说明**（对第 3 节官方参数逐条）。
4. 程序源代码：只版本化代码/配置/文档（`.gitignore` 挡 mp4、权重、log），附运行说明。
